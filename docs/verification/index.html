How a human records a decision

This page cannot record your decision, and neither can any agent. Tool separation, an actor-class gate, an independence requirement and a determinism cap all exist for one reason: an agent must never be able to promote work to HUMAN VERIFIED (design §5.3). A page that offered a button would be that promotion with extra steps. You edit the claims file yourself, in a pull request.

AGENT VERIFIED is not a step toward HUMAN VERIFIED. It is a different assertion by a different actor, and it neither advances toward nor substitutes for a human's judgement (design §5.2).

The marker grammar (design §3.4)

— <STATE> (PR #<n>, YYYY-MM-DD)
  • Append it as a continuation line under the claim, in plugin/scripts/fixtures/slice/llm/claims.md, indented to match the lines already there.
  • Append only. Never edit and never delete an existing marker. The current state is the last line; the lines above it are the history, and that history is the record (design §3.5).
  • An absent marker means NOT VERIFIED. That default costs nothing to adopt and cannot be forged by omission (design §3.4).
  • No free prose inside the parentheses. A reason is permitted only on a reset, as the existing — NOT VERIFIED (claim text edited, …) line shows.
  • Before writing HUMAN VERIFIED: run the REPLAY and the MODIFIED REPLAY yourself, and check that the modified one failed. On L3/L2 evidence a MODIFIED REPLAY that failed as it should is required (design §14.4). On L1 evidence the state is unavailable at any price.

The three verification modes (design §14.2)

REPLAYRe-execute the recorded command with the recorded inputs; expect the recorded result. Proves the artifact is reproducible.
MODIFIED REPLAYRe-execute with a deliberate perturbation that should change the outcome — mutate an input, break a precondition, delete the thing being asserted about. Expect failure. Proves the check is not vacuous. A check that passes under perturbation is asserting nothing.
INDEPENDENT VERIFICATIONA distinct actor, in a distinct session, with no access to the builder's reasoning, produces evidence from the claim text alone. Proves the result is not an artifact of how it was built. Independence here is temporal and artifactual, not identity-based.

The three determinism levels (design §14.1)

levelnamedefinitionverified by
L3DeterministicSame inputs produce byte-identical outputs.Re-execute; compare `sha256`.
L2Executable, non-deterministicRuns to a pass/fail, but the output is not byte-stable (timestamps, network, cloud state, LLM sampling).Re-execute; compare assertions, not bytes.
L1AttestedA human or an agent states it. There is nothing to re-execute. It is testimony.Nothing. It cannot be re-executed.

Determinism and verification are two axes, never one boolean. A deterministic check can be consistently wrong, and an attested claim can be true. The level bounds what re-execution can tell you; it does not tell you whether the claim holds.
